# Writing a good bug bounty report
Tags: report writing, reproduction steps, impact statement, bugcrowd, hackerone, triage

A strong report lets the triager reproduce the issue in minutes. Use a specific title (vulnerability class + affected function), a one-paragraph summary, numbered reproduction steps with the exact request, the observed versus expected result, a concrete impact statement, and a remediation suggestion.
Redact real session tokens and other users' personal data, using your own test accounts wherever possible.
Stay inside the program scope and rules of engagement; note the test accounts used and the time of testing.
Avoid speculative impact. Describe what you demonstrated, and label anything further as potential.
